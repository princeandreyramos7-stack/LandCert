# Requirements Document

## Introduction

This document specifies requirements for a major system revision to transition from digital/online payment and certificate workflows to physical/offline processes. The system currently supports online payment receipt submission with admin verification and automatic digital certificate generation. The revised system will generate payment orders for treasury-based cash payments (with staff manually recording payment completion), require physical certificate collection at the CPDO office with manual signatures, and add automated requirement submission at configured deadlines. There is no online payment submission or approval workflow - applicants pay cash at the treasury and staff simply record that payment was completed.

## Glossary

- **System**: The Laravel-based land certification application management system
- **Payment_Order**: A document generated by the System containing payment details for treasury submission
- **Treasury**: The government office where applicants make cash payments
- **Certificate**: A physical document requiring manual signatures from higher positions before collection
- **CPDO_Office**: City Planning and Development Office where certificates are collected in person
- **Applicant**: A user who has submitted a land certification application
- **Staff**: Administrative users who process applications and manage workflows
- **Requirement_Submission**: The process of submitting application requirements at a scheduled deadline
- **Submission_Deadline**: A configurable date/time when requirements are automatically submitted
- **Treasury_Receipt**: Physical proof of payment obtained from the Treasury by the applicant
- **Workflow_Status**: The current state of an application in the processing pipeline

## Requirements

### Requirement 1: Remove Online Payment Submission and Approval Workflow

**User Story:** As a system administrator, I want to remove online payment receipt submission and approval features, so that the system aligns with the new treasury-based cash payment process.

#### Acceptance Criteria

1. THE System SHALL remove the payment receipt upload functionality from the applicant interface
2. THE System SHALL remove the payment receipt verification workflow from the admin interface
3. THE System SHALL remove the payment approval and rejection actions from the admin interface
4. THE System SHALL remove all payment submission status transitions (pending, verified, rejected) from the workflow
5. THE System SHALL remove email notifications related to payment receipt submission, approval, and rejection

### Requirement 2: Generate Payment Orders

**User Story:** As an applicant, I want to receive a payment order document after my application is approved, so that I can pay at the Treasury office.

#### Acceptance Criteria

1. WHEN an application is approved, THE System SHALL generate a Payment_Order document
2. THE Payment_Order SHALL include the applicant name, application reference number, payment amount, and treasury payment instructions
3. THE System SHALL make the Payment_Order available for download in the applicant dashboard
4. THE System SHALL send an email notification to the Applicant with the Payment_Order attached
5. THE Payment_Order SHALL include a unique order reference number for treasury tracking

### Requirement 3: Track Treasury Payment Completion

**User Story:** As staff, I want to manually record when applicants have completed payment at the Treasury, so that I can track payment completion without any online submission or approval workflow.

#### Acceptance Criteria

1. THE System SHALL provide a staff interface to mark applications as "payment completed"
2. WHEN Staff marks payment as completed, THE System SHALL record the payment completion date
3. WHEN Staff marks payment as completed, THE System SHALL record the staff member who confirmed payment
4. THE System SHALL allow Staff to enter the Treasury_Receipt number for reference
5. THE System SHALL update the Workflow_Status to "payment_completed" when payment is confirmed
6. THE System SHALL not require any payment receipt file upload or approval process

### Requirement 4: Remove Automatic Digital Certificate Generation

**User Story:** As a system administrator, I want to remove automatic PDF certificate generation, so that the system supports the new physical certificate process with manual signatures.

#### Acceptance Criteria

1. THE System SHALL remove the automatic certificate PDF generation functionality
2. THE System SHALL remove the certificate download feature from the applicant interface
3. THE System SHALL remove the certificate email delivery functionality with PDF attachments
4. THE System SHALL remove all certificate template views and PDF generation code
5. THE System SHALL remove the certificate file storage functionality

### Requirement 5: Manage Physical Certificate Collection

**User Story:** As staff, I want to track when applicants collect their physical certificates at the CPDO office, so that I can maintain accurate records of certificate distribution for certificates that have been manually signed.

#### Acceptance Criteria

1. THE System SHALL provide a staff interface to mark certificates as "ready for collection" after manual signatures are obtained
2. WHEN a certificate is marked ready for collection, THE System SHALL send an email notification to the Applicant
3. THE System SHALL provide a staff interface to record when an Applicant collects their certificate in person
4. WHEN Staff records certificate collection, THE System SHALL capture the collection date and time
5. WHEN Staff records certificate collection, THE System SHALL capture the staff member who processed the collection
6. THE System SHALL allow Staff to enter the physical certificate number for tracking
7. THE System SHALL update the Workflow_Status to "certificate_collected" when collection is recorded

### Requirement 6: Notify Applicants of Physical Collection Requirement

**User Story:** As an applicant, I want to be notified when my certificate is ready for collection, so that I know when to visit the CPDO office.

#### Acceptance Criteria

1. WHEN a certificate is marked ready for collection, THE System SHALL send an email to the Applicant
2. THE email SHALL include the CPDO_Office address and operating hours
3. THE email SHALL include instructions for what documents to bring for collection
4. THE email SHALL include the certificate reference number
5. THE System SHALL display the collection status in the applicant dashboard

### Requirement 7: Configure Automated Requirement Submission Deadline

**User Story:** As staff, I want to configure automatic submission deadlines for application requirements, so that requirements are submitted at the specified deadline time without manual intervention.

#### Acceptance Criteria

1. THE System SHALL provide a staff interface to set a Submission_Deadline for each application
2. THE System SHALL allow Staff to specify the deadline as a date and time
3. THE System SHALL validate that the Submission_Deadline is in the future when initially set
4. THE System SHALL display the configured Submission_Deadline in the applicant dashboard
5. THE System SHALL allow Staff to modify the Submission_Deadline before it occurs

### Requirement 8: Execute Automated Requirement Submission at Deadline

**User Story:** As an applicant, I want my requirements to be automatically submitted at the configured deadline time, so that I don't need to manually submit them.

#### Acceptance Criteria

1. WHEN the Submission_Deadline time is reached, THE System SHALL automatically submit the application requirements
2. THE System SHALL update the Workflow_Status to "requirements_submitted" when auto-submission occurs
3. WHEN auto-submission occurs, THE System SHALL send an email notification to the Applicant confirming submission
4. WHEN auto-submission occurs, THE System SHALL send an email notification to Staff that requirements were submitted
5. THE System SHALL log the auto-submission event with timestamp and application details
6. IF the Submission_Deadline is reached and requirements are incomplete, THEN THE System SHALL still submit and send an email notification to the Applicant indicating incomplete submission
7. THE System SHALL use a scheduled task or cron job to check for deadlines and trigger auto-submission

### Requirement 9: Update Workflow Status Transitions

**User Story:** As a system administrator, I want to update the workflow status values to reflect the new payment and certificate processes, so that the system accurately tracks application progress through the physical workflow.

#### Acceptance Criteria

1. THE System SHALL replace "payment_submitted" status with "payment_order_generated"
2. THE System SHALL remove "payment_verified" and "payment_rejected" statuses from the workflow
3. THE System SHALL add "payment_completed" status for when staff records treasury payment
4. THE System SHALL replace "certificate_issued" status with "certificate_ready_for_collection"
5. THE System SHALL add a new status "certificate_collected"
6. THE System SHALL update all workflow status transitions to use the new status values
7. THE System SHALL migrate existing records to use the new status values
8. THE System SHALL ensure the workflow sequence is: approved → payment_order_generated → payment_completed → certificate_ready_for_collection → certificate_collected

### Requirement 10: Preserve Historical Payment Data

**User Story:** As a system administrator, I want to preserve existing payment records during the transition, so that historical data from the old online payment workflow is not lost.

#### Acceptance Criteria

1. THE System SHALL retain the payments table in the database
2. THE System SHALL mark fields related to online payment submission (payment_status, receipt_file_path) as deprecated
3. THE System SHALL retain historical payment records for reference
4. THE System SHALL prevent new payment records from being created through the deprecated online submission workflow
5. THE System SHALL allow Staff to view historical payment records in read-only mode

### Requirement 11: Preserve Historical Certificate Data

**User Story:** As a system administrator, I want to preserve existing certificate records during the transition, so that historical data from the old digital certificate workflow is not lost.

#### Acceptance Criteria

1. THE System SHALL retain the certificates table in the database
2. THE System SHALL mark the certificate_file_path field as deprecated
3. THE System SHALL retain historical certificate records for reference
4. THE System SHALL prevent new certificate PDF files from being generated
5. THE System SHALL allow Staff to view historical certificate records in read-only mode

### Requirement 12: Update Email Templates for Physical Processes

**User Story:** As a system administrator, I want to update email templates to reflect the new physical processes, so that applicants receive accurate information about treasury payments and physical certificate collection.

#### Acceptance Criteria

1. THE System SHALL update the application approval email to mention payment order generation and treasury payment process
2. THE System SHALL update the welcome email to describe the treasury-based cash payment process
3. THE System SHALL remove references to online payment receipt submission from all email templates
4. THE System SHALL remove references to digital certificate download from all email templates
5. THE System SHALL add references to physical certificate collection at CPDO_Office in relevant emails
6. THE System SHALL create a new email template for payment order delivery with treasury instructions

### Requirement 13: Remove Payment Reminder Functionality

**User Story:** As a system administrator, I want to remove automated payment reminders, so that the system does not send reminders for the deprecated online payment submission process.

#### Acceptance Criteria

1. THE System SHALL remove the payment due reminder email functionality
2. THE System SHALL remove the scheduled job that sends payment reminders
3. THE System SHALL remove payment reminder configuration from the admin interface
4. THE System SHALL remove the PaymentDueReminder mail class
5. THE System SHALL remove payment reminder related code from the ReminderService
6. THE System SHALL retain other reminder functionality (document pending, certificate expiry) that is still relevant

### Requirement 14: Update Dashboard Statistics

**User Story:** As staff, I want dashboard statistics to reflect the new workflow statuses, so that I can monitor application progress accurately.

#### Acceptance Criteria

1. THE System SHALL update dashboard statistics to count applications by new workflow statuses
2. THE System SHALL display count of applications with "payment_order_generated" status
3. THE System SHALL display count of applications with "payment_completed" status
4. THE System SHALL display count of applications with "certificate_ready_for_collection" status
5. THE System SHALL display count of applications with "certificate_collected" status
6. THE System SHALL remove statistics related to deprecated payment verification workflow

### Requirement 15: Update Audit Logging

**User Story:** As a system administrator, I want audit logs to capture the new workflow actions, so that all system changes are properly tracked.

#### Acceptance Criteria

1. WHEN a Payment_Order is generated, THE System SHALL log the event with application details
2. WHEN Staff marks payment as completed, THE System SHALL log the event with staff member and timestamp
3. WHEN a certificate is marked ready for collection, THE System SHALL log the event with staff member and timestamp
4. WHEN a certificate is collected, THE System SHALL log the event with collection details
5. WHEN automated requirement submission occurs, THE System SHALL log the event with submission details
